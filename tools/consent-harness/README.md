# Consent startup correction tests

From the repository root: `sh tools/consent-harness/run.sh`.

The first executable compiles the actual Foundation-only AdConsentCoordinator. The second compiles the actual AdReviveManager body, substituting only its platform imports and supplying explicit UIKit, Google SDK, StoreKit-state and service fakes. It tests all six placements, deferred/repeated warm requests, stale callback/cache rejection, privacy revocation, Remove Ads benefits, reward exactly-once behavior and dismissal-triggered reloads. No test contacts ad services. These are policy/order tests, not evidence of SDK network privacy or regional dashboard configuration.

Native iPad XCTest source and its standalone project are in `native/`; results are retained in the task evidence packet (`v22-consent-fix/native-input`). Build/install the isolated Debug app on a disposable iPad first, then run SFPrivacyPlaytest with only testFreshAllowAndPersistedChoice or testFreshDenyAndPersistedChoice on separate fresh devices. These tests terminate/relaunch only their installed target app. Debug launch argument `--privacy-att-system-test` uses the real iOS ATT API while stubbing UMP and MobileAds initialization and forbidding rewarded loads. Its visible probe explicitly labels these stubs. `--privacy-debug-probe` only exposes Debug diagnostic state and uses real UMP. Neither probe exists in Release. Do not use either argument for distribution acceptance or describe the OS-only proof as production UMP validation.

The entitlement revision also compiles the actual IAPManager body against an explicit StoreKit transport fake (only the import and test initializer access differ). DEBUG is undefined in this executable, so it executes the production entitlement enumeration, purchase, restore and transaction-listener paths. Completed verified snapshots, unverified/error states, delayed ownership, stale snapshot races, revocation and concurrent restore/purchase behavior are covered. These tests do not establish real billing or offline StoreKit behavior.

The native `testEntitlementOwnerAndUnknownGameplay` uses explicit Debug-only `--privacy-entitlement-test=owner`, `unknown` and `delayed-owner` transports on disposable profiles. Its probe labels StoreKit as STUBBED. It checks closed UMP/ATT/SDK startup, actual GameScene entry with unknown entitlement, delayed ownership and relaunch. It does not simulate a real App Store purchase. Fresh Allow/Deny tests use real system ATT and StoreKit resolution, while UMP/SDK remain explicitly stubbed. No entitlement test transport exists in Release.
