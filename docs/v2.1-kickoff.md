## Unit sequence

### Unit 0 — Arena unlock registry (UNBLOCKED, starts immediately)

The consolidation banked after the Arena 5 bug (`arena-unlock-registry-v21`
in memory). No player-visible change; behavior-identical for arenas 1–5.

1. `ArenaConfig` gains `bossID` + `bossName` per arena — the single source
   of truth for arena↔boss pairing.
2. One `registerArenaBossDefeat(...)` chokepoint in ProgressionManager:
   records the defeat AND derives the next-arena unlock. Every boss
   `onDeath` calls it; the five hand-written unlock lines disappear.
3. TitleScene derives locked-card requirement text, next-arena
   announcements, and gate lines from `ArenaConfig` — both hand-maintained
   switches disappear.
4. Launch-time reconciliation: recompute unlocks from `defeatedBosses` +
   the registry (keep the stored int + single write chokepoint — Boss Mode
   semantics unchanged). Makes the v2.0.1 save-heal permanent: any future
   missed unlock self-repairs. The v1.7 Warden and v2.0.1 Faceted Lie
   migrations collapse into it.

**DoD:** build clean, zero new warnings. Sim validator matrix (Claude):
per-arena seeded saves show identical card text/unlock behavior to 2.0.1;
reconciliation heals a stranded save; fresh save unchanged. Brandon: device
spot-check on his live save (nothing should look different — that's the
pass).

### Unit 1 — Capstone AoE audit (unblocked; slots wherever pacing allows)

The ⭐ v2.1 lens from memory: audit ALL capstones for single-target
falloff during the pre-boss swarm; splash ≈50% of primary where warranted,
never a second damage source. Boss-class scaling (debuffScale/damageScale)
applies. Also closes the open retrofit: Everglow / Iron Maiden damage paths.

### Unit 2 — Geometry reconnaissance (Lyra's discovery request, §11)

The compact technical recon packet before any geometry code: pursuit/steer
model, physics categories + contact assumptions, spawn/point sampling,
which attacks assume an open field, Growth/Panda/orbital/dash behavior near
blocked geometry, single-playfield assumptions in arena + Boss Mode code,
smallest data structure for obstacles + two-route navigation, perf risk on
oldest devices, existing debug/test seams, and recommended unit boundaries
with proof criteria. **Read-only; the deliverable is the map, not code.**

### Units 3+ — The Splitworks (sequenced per the design lock §12)

Lyra's proposed production sequence, adopted (numbers shifted to follow the
units above): geometry foundation + Splitworks shell with debug overlays →
Spurhound / Linekeeper / Ramplate one at a time → The Marchwarden →
progression + Marchworn earned skin + 4 bestiary entries (Arena 5 process)
+ art/sound + Boss Mode compat → integration, tuning, telemetry closeout.
Unit boundaries may shift after the Unit 2 recon; the lock's §13 scope
table and §15 acceptance criteria govern.

**Cutline honesty:** at ~1-week sprint cadence this is 3–4 sprints wearing
one version number. The spine is registry → recon → geometry foundation →
roster → boss; the AoE audit re-slots freely, and per the divergence calls
above, Rainbow and element omission are already off this train.

## Standing hygiene (from the 2.0.1 retro)

- No silent `#if DEBUG` progress-granting seams. Dev aids announce
  themselves or don't exist. Debug builds run the real progression.
- Every new gated system states, in its kickoff unit, WHERE the gate reads
  from — one registry, not a new scattered site.
