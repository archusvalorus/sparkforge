# Sparkforge v2.1 — Signature Cards: the tree-entry sub-system

*Brandon's ask, Aug 10 2026: every tree gets a "signature" card that
modifies BASIC ATTACKS on purpose — a theme that rides along each choice.
The signature is the tree's mandatory first pick; the tree's other cards
open behind it; the synergies are where the real fun lives. Deterministic
first picks are the point: no run dies to a bad opening spread, every
choice carries weight, and it's a different way to engage. One
sub-system, everything inherits. Reconciled against the engine by Claude.*

## The good news: the foundation already exists

The v2.0 eligibility layer (`UpgradeCard.provides` / `.requires`, in
`UpgradeManager.drawCards`) was built for exactly this and its own comment
forbids building a second one. **Terra is already a signature card in
everything but name**: it `provides: .growthUnlocked`, all seven other
Growth cards `requires: .growthUnlocked`, and GATEWAY PITY guarantees a
gateway surfaces within N level-ups. Growth was the pilot; the studio
just didn't call it that.

Signature cards = **that pattern, applied to all eight trees, plus one
new rule** (the deterministic offer, below).

## Design (proposed, for Brandon's confirmation)

### 1. One signature per tree

| Tree | Signature (per Brandon's rework notes) | Basic-attack modification |
|---|---|---|
| Fire | Kindle | projectiles ignite |
| Chill | Frost Touch | projectiles slow |
| Shock | Chain Lightning | hits chain |
| Growth | Terra | *(already wired)* — cultivate; unlocks the tree |
| Bleed | *(pending notes)* | expect: hits bleed |
| Guard | *(pending notes)* | expect: a defensive on-hit/on-taken rider |
| Void | *(pending notes)* | expect: hits pull / warp |
| Neutral | none — neutral is not a tree, it's the palette's constant | — |

Data: `UpgradeCard.isSignature: Bool` + each signature `provides` a
per-tree capability (`.fireUnlocked`, `.chillUnlocked`, …); every
non-signature card in the tree `requires` it. That is the whole schema —
two existing fields and one new flag.

### 2. The deterministic-first-pick rule (the new mechanic)

**Rule:** while the run holds ZERO signature cards, the level-up spread
offers ONLY signature cards — one per active tree, up to the spread size.
The moment the first signature is taken, drawing returns to normal, and
each other tree's non-signature cards stay gated behind their own
signature via `requires` (surfacing through gateway pity, as Terra does
today).

Consequences, all intentional:
- Level 1's spread is "pick your first identity" — 3 of the run's 5
  active trees, each represented by its thesis card. Legible, weighty.
- A second/third tree opens the same way Growth does today: its
  signature appears in a normal spread (with pity), and taking it unlocks
  the rest. Breadth builds stay possible; they just *commit* to each tree.
- Neutral cards keep flowing (they need no signature) — the +stat / XP /
  utility picks are never gated.
- Reroll on the first spread re-shuffles WHICH signatures show (if >3
  active trees), never escapes the rule.

### 3. Interaction with existing systems (all verified in code)

- **Palette roll** (5 of 7 trees active): unchanged. Only active trees'
  signatures are offered. Ban still honored.
- **Gateway pity**: already keys off `!provides.isEmpty` — every
  signature automatically inherits pity with ZERO changes. (Pity is why
  a tree you didn't open first still becomes findable.)
- **Boss Mode opener draft** (8 auto-picks): rounds 1..N draw through
  the same `drawCards`, so the first draft round becomes a signature
  choice too — good, it means gauntlet builds also commit. Confirm.
- **Panda**: secret, scheduler-injected, `isSecret` bypasses the pool.
  Untouched. Pandas remain pandas.
- **Capstone focus & finish**: orthogonal (capstones are T5 of a card
  you already own; you can't hold one without holding the tree's
  signature first). No conflict.
- **Codex / lifetime discovery**: signatures are ordinary cards; nothing
  new to persist. `sf_` keys untouched.
- **Card-offer eligibility canon** ("never offer an amplifier before its
  enabler"): this IS that rule, generalized — the signature is the
  enabler for its whole tree.

### 4. Open calls (Brandon)

- **Q1 — Spread size at level 1** with only 3 slots and 5 active trees:

- **Q2 — Reroll ad on the signature spread**: allowed (re-shuffles the
  3 shown) or disabled for the deterministic pick? Recommend allowed.
- **Q3 — Should the SECOND tree also be forced-offered** at some point
  (e.g. by level 4 if the player is still mono-tree), or is pity enough?

- **Q4 — Neutral in the first spread**: excluded (pure identity choice)
  or allowed as a 4th "no commitment yet" option? Recommend excluded.
- **Q5 — Boss Mode draft**: confirm the opener draft's round 1 becomes

## Build shape (Claude, once confirmed) — one unit

1. `isSignature` + per-tree capabilities on `UpgradeCard` / `Capability`.
2. `drawCards`: the zero-signature branch (offer signatures only) — a
   ~15-line guard ahead of the existing pool filter. Everything else
   inherits.
3. Author the `provides`/`requires` on all seven trees' cards (data only;
   done alongside the rework spec, since card lists are changing anyway).
4. Atlas: show the signature crown per tree + gate lines already render.
5. Validators: fresh run → level-1 spread is signatures only; taking one
   opens exactly its tree; a second tree's signature surfaces via pity;
   Boss Mode draft round 1 obeys; panda unaffected; palette/ban unaffected.

Sequencing: **build with the card rework**, not before it — the
`provides`/`requires` authoring touches the same card definitions the
rework is rewriting, so it's one pass over the pool, not two.
