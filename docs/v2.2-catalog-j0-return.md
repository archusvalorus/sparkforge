**Recommendation in one paragraph.** The kickoff's architecture holds up against the source: move the 80 card definitions, the 21 synergy lines and the 8 retired ids into one ordered, versioned JSON file; keep every effect closure, every number and every draft rule in Swift; join the two at load time by a validated behaviour key. Three rulings are needed before J1 (D1–D3 below); two more before J3. Recommended next unit: **J1**, after those three rulings.

## 1. What exists

**The catalog is one function.** `UpgradeManager.buildCardPool()` (`Sparkforge/Systems/UpgradeManager.swift:1181`) appends 80 `UpgradeCard` values. Synergy copy is a second switch (`synergyTiers(for:)`, line 1104), synergy effects a third (`applySynergy`, line 995), retired ids a static dictionary (line 1146).

**Inventory, confirmed by the export and the harness (CA1–CA3):** 80 cards = 79 draftable + the secret Panda; 10 regular Neutral; 7 signatures; 7 capstones; 21 synergy tiers; 8 retired ids. Also: 148 tiers in total across 24 laddered cards (one 2-tier, eleven 3-tier, three 4-tier, nine 5-tier); 48 cards carry a `detail`; 4 dual-tag cards (Deeproot, Relay Burn, Silver Skin, Red Smile); 14 capabilities in use; 3 cards with tier-level gates (Frost Touch T3, Glacial Drift T5, Polar Vortex T4).

**Facts that shape the contract:**

- **No copy is generated.** There is no string interpolation in the card pool or the synergy copy. Every number a player reads ("+25% Fire damage") is typed into the string by hand, separately from the value the effect reads (`GameConfig.Fire.forgeBreathBonus`). The two are kept in step today by review, the CP copy pins and the canon.
- **Card order is behaviour, in three places.** The shuffle input is `allCards` filtered in order, so order decides every seeded draft. Two capstones in progress get their guaranteed seats on parities set by their order in `allCards`. Gateway pity breaks a tie in waiting time by first-in-order.
- **The base face and the tier-1 face are different fields.** Nine cards show one line on the detail surfaces (`description`) and another as tier 1 (`tierDescriptions[0]`): Frost Touch, Glacial Drift, Tree and the six v1.9 capstones. Both must migrate.
- **One tier count comes from tuning.** Siphon's rungs are built by mapping over `GameConfig.Bleed.siphonHealTotals`, so its max tier is that array's length.
- **Some effects live outside the catalog, keyed by card id.** `GameScene` acts on `v20_wildbloom`, `v20_vinewall`, `v20_tree` and `v20_richsoil` at both pick sites (the level-up commit and the random opener), on any Growth card by tag, and on `GameConfig.Panda.cardID`. Wildbloom's catalog closures are empty on purpose. `checkBuildHint` names eight more ids, across five hints. *(Corrected in J1, Oct 5: this line first said five ids.)*
- **Persisted strings that must not move:** card ids (`sf_cards_offered`, run analytics), `Tag` raw values (`sf_bannedFamily` stores "Fire"; `sf_synergies_seen` stores "Fire_3"), `GameConfig.Panda.cardID`.
- **Ten harness runners compile the real `UpgradeManager.swift`** on the host with Foundation only (catalog, signature-draw, damage-pipeline, fire, chill, shock, bleed, redsmile, guard, void). None has an app bundle.
- **The app target uses a file-system-synchronized group.** A file added under `Sparkforge/` is bundled without a project-file edit (the BGM tracks already rely on this), so the migration need not touch the dirty `project.pbxproj`.
- **Two small inefficiencies the cutover removes for free:** `UpgradeManager.catalogIDs` rebuilds the whole pool on every call, and the Card Codex builds a throwaway `UpgradeManager` (rolling a palette and a Panda chance) only to read the card list.

**Where each card's numbers live today** (`tools/v2.2-catalog/baseline/tuning-ownership-inventory.json`, a source-text heuristic):

| Kind | Cards | Meaning |
|---|---|---|
| switch | 35 | The effect sets a flag or a tier. The numbers live where the flag is read: `PlayerStats`, the scene, a node, or `GameConfig`. |
| config | 21 (+3) | Every number comes from `GameConfig`. Static, Surge and Glass Engine are listed as "mixed" only for the `1 +` in their rate formula. |
| literal | 18 (+1) | A number is typed into the effect: Kindle, Chain Lightning, Brace, all ten regular Neutral cards except Chain Reaction and Overclock, Overcharge, Execution Protocol, Open Vein, Thornsoil, Rich Soil, Deeproot, Mirror Edge. Everglow adds two in-place `×2` steps. |
| none | 1 | Wildbloom: empty closures; the scene grows the flower. |

Synergy effects follow the same split: 5 of the 21 read `GameConfig`, 12 carry a typed number (Absolute Zero does both), and 5 only set a flag.

## 4. Proposed schema and interfaces (deliverable 3)

Contract examples only. The copy below is the current copy, abbreviated where marked `…`.

### 4.1 File shape

```json
{
  "schema": "sparkforge.ability-catalog",
  "schemaVersion": 1,
  "trees": [
    { "key": "fire", "name": "Fire" }, { "key": "shock", "name": "Shock" },
    { "key": "bleed", "name": "Bleed" }, { "key": "guard", "name": "Guard" },
    { "key": "void", "name": "Void" }, { "key": "chill", "name": "Chill" },
    { "key": "growth", "name": "Growth" }, { "key": "neutral", "name": "Neutral" }
  ],
  "capabilities": ["growthUnlocked", "fireUnlocked", "…"],
  "cards": [],
  "synergies": [],
  "retired": [{ "id": "v13_static_field", "note": "A2 Chill (Static Field)" }]
}
```

- `trees[].key` is the portable key (`guard`, `void`); Swift maps it explicitly to `Tag.guardT`, `Tag.voidT`. `trees[].name` must equal `Tag.rawValue`, which live saves freeze.
- `cards` is ordered; the loader preserves the order exactly.
- A card with no `tiers` has one tier. With `tiers`, the list length is the max tier. Per-tier gates sit on the tier they belong to and map one-to-one onto today's `tierRequires` / `tierProvides` / `tierBlockedBy`. Tier 1 carries no gates of its own (no card uses that today; card-level `provides` / `requires` already mean it), so each fact has one spelling.
- Unknown keys are rejected in version 1.

### 4.3 Native interfaces

```swift
/// A card's effects, tier 1 first. `tiers.count` is the native max tier.
struct CardBehavior {
    let tiers: [(PlayerStats) -> Void]
}

enum AbilityBehaviors {
    static let cards: [String: CardBehavior]                   // key = a definition's "behavior"
    static let synergies: [String: (PlayerStats) -> Void]      // key = "<tree>.<threshold>"
}

struct AbilityCatalog {
    let cards: [UpgradeManager.UpgradeCard]                    // in file order, closures bound
    let synergies: [UpgradeManager.Tag: [UpgradeManager.SynergyTier]]
    let retired: [String: String]

    /// Pure and Foundation-only. Returns a whole catalog or throws; never a partial one.
    static func load(_ data: Data) throws -> AbilityCatalog
}

enum CatalogError: Error {          // each carries the offending id / key / value
    case malformed, unsupportedSchemaVersion, unknownField
    case treesMismatch, unknownTree, unknownCapability
    case duplicateID, retiredIDIsLive, emptyCopy
    case missingBehavior, tierCountMismatch, unboundBehavior
    case synergyLadderMismatch, missingSynergyBehavior
    case secretCardMismatch, nativeIDMissing    // Panda's id; the scene and build-hint ids
}
```

- `load` collects every problem it can find and reports them together, so one run of the harness names all of them.
- A behaviour key may be bound by more than one card (that is what makes an existing-behaviour card cheap). A behaviour bound by no card is an error.
- The only code that knows where the file is sits in its own small file. The app's version reads the bundle; the harnesses' version (in the shared stubs) reads a path the runner passes and fails if none is given. `UpgradeManager.swift` stays compilable by all ten runners unchanged in kind.
- The catalog is parsed once and cached.

## 5. Parity strategy (deliverable 5)

The smallest set that covers each item the kickoff lists. "Existing" means a check that already runs and keeps running against the JSON-built catalog without change, because it reads the catalog through `UpgradeManager`'s API.

| What must hold | Evidence |
|---|---|
| Exact ordered metadata | **New, J1.** The same `--dump` code run over the legacy pool and over the loader's output must produce identical bytes, and both must equal the J0 export. After cutover the J0 export is the fixture. |
| The canon is undisturbed | **Existing.** The canon's fingerprint takes the dump as an input, so `--check` passing with the same `catalog` digest (`ee3209d5…`) after cutover is an independent proof. |
| Effects and state deltas, every card and tier | **New, J1.** A reflective snapshot of `PlayerStats` before and after each tier, from the default state and from two or three seeded non-default states (Glass Engine, Iron Maiden and Thornsoil read the state they change). Recorded once from the legacy closures as a fixture; the JSON-bound behaviours must reproduce it exactly. |
| Relevant combinations | **New, J1.** A few hundred seeded whole-run acquisition sequences; the final stats snapshot per seed is recorded and compared. This covers order-dependent stacking without enumerating pairs. |
| Seeded draft and acquire sequences | **New, J1, cheap.** A transcript (spreads, rerolls, bonus card, picks) for a fixed seed list on a full save and a new save, recorded from legacy and compared. **Existing:** RS, RW, IS. |
| Gates in both directions | **Existing:** CA (every gate's provider), EG, AQ, SY, SL. Their mutants that edit card metadata move from Swift text to JSON text (section 6). |
| Synergies | **New, J1:** deltas for all 21, from the default and a post-card state. **Existing:** CP3, CP6, WR16 (re-pointed, section 6). |
| Reset, Codex discovery, retired ids, secret scheduling | **Existing:** PB, CT, PA. Plus the loader rule that a retired id is never live. |
| Numeric and config ownership | **New, J2.** `inventory.py` pointed at the behaviours file must list the same `GameConfig` reads and the same literals per card as the J0 inventory. |
| Bundle loading | **New, J2.** The built `.app` contains the file; a launch in the simulator loads it (a DEBUG log line with schema version and card count); the harness loads the same file from the app's source path. |
| Invalid schema and missing effects | **New, J1.** One isolated fixture per `CatalogError` case; each must throw that error, and none may return a catalog. |

The two recorded fixtures (effect deltas, draft transcripts) are generated output, never edited, and live beside the J0 export. They are the "legacy snapshot" the kickoff allows: a parity fixture, not a second catalog.
