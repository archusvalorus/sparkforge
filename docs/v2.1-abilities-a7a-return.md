**Known Atlas-tooling limitations** (the freeze-13 Reviewer findings; accepted as valid, **non-blocking** under the revised Atlas status, and kept on record, not erased). Each finding is as given; the note after it is Claude's pointer into the tool.
1. **Complex stylesheet hiding semantics are not completely modeled.** The stylesheet rule is a pattern check for a fixed list of hiding declarations. Other ways a stylesheet can hide or rearrange text are not evaluated.
2. **Hidden template Git text can evade the current file-level scan.** `<style>`, `<script>`, `<template>` and `<head>` subtrees are skipped by every channel, including the "all" channel the Git scan reads.
3. **Some equivalent inline-wrapper arrangements fail.** Item boundaries come from a tag vocabulary (formatting tags join adjacent text; other elements break) that approximates rendering without CSS. Some arrangements a browser renders identically resolve differently.
4. **`aria-hidden` behavior does not fully match the previously attempted visual-equivalence policy.** `aria-hidden` counts as hidden for the required shown label but as present for duplicate counting.

### Fit rules used (all checked against the code, not assumed)

**Selection-card face** (`UpgradeCardNode.swift:203-217`)
- Wrapping is greedy by word, 17 characters per line (`descMaxChars`), up to 4 lines (`descMaxLines = 4`).
- If a card has a `detail`, or its text runs past 4 lines, a MORE chip takes the 4th line. Anything that still doesn't fit is cut with "…".
- The budget is therefore **3 lines with a detail and 4 without.**
- Which text shows:
  - An unowned card shows `description`.
  - An owned card at tier t shows `tierDescriptions[t]`, the next tier's line.
  - **`tierDescriptions[0]` (the T1 rung) is never shown on a face.** It appears only in the MORE/Codex ladder, wrapped at 38.
  - Note that the Fire harness D1 and the other tree harnesses test `description(forTier: 1…max)`, which does include the T1 rung, against the same budget.

**Detail modal** (`CardDetailNode.swift`)
- Nothing in the modal has a line cap and it doesn't scroll. The panel simply grows with its content, and it is centred.
- The smallest supported iPhone is the SE 2/3, whose scene is **667pt** tall (iOS 26.2, portrait-only). Anything taller gets clipped at the top and bottom.
- I modelled the height from the node's own constants: name 30, chips 34, owned tier line 18, each rung 14+13×lines@38+5, detail 6+13×lines@40, synergy block 44+Σ(21+13×lines@40), footer 60.
- As built today, **Iron Maiden is 730pt (already clipped on an SE)** and **Phase is 666pt**. The CL-88 pass evidently kept Phase inside 667, so I held every proposal below to **665pt or less, in-run**.

**Synergy copy: yes, it has a fit constraint.**
- **Synergy Codex chip** (`SynergyCodexNode.swift:57,192`)
  - Wrapping is `Int(chipW / 6.2)` characters per line, where `chipW = (sceneWidth − 48) / 3`. That gives **17 characters at 375pt** (SE 2/3, 12/13 mini), 18 at 390/393, 19 at 402/414, 20 at 428/430, and 21 at 440.
  - The chip shows **only 3 lines (`.prefix(3)`) and silently drops the rest.** There is no "…".
  - So a synergy line has to fit **3×17** to read in full on every supported iPhone.
- **Unlock reveal and capstone reveal** (`SynergyUnlockNode.swift:103`) wrap at 34 with no cap. This is also where a capstone's T5 line appears.
- **Detail-modal synergy block** wraps at 40 with no cap, but it counts toward the 667pt modal height above.

**The model.** Rebuilt on a parsed ELEMENT TREE (stdlib `html.parser`; entities decoded; tags case-insensitive).

**1. Inherited visibility.** Each element carries three inherited flags:

| Flag | Set by | Effect |
|---|---|---|
| **not rendered** | the `hidden` attribute, or inline `display:none` / `visibility:hidden\|collapse` / `content-visibility:hidden` (`!important` and comments tolerated) | off screen AND out of the accessibility tree |
| **aria-hidden** | `aria-hidden="true"` | out of the accessibility tree, still painted |
| **faded** | inline `opacity:0` / `font-size:0` | painted invisibly, still read out |

- Hidden descendant text never contributes to an ancestor's text: a hidden element is removed before its siblings are flattened.
- **The stylesheet may hide nothing.** `display:none`, `visibility:hidden`, `opacity:0`, `font-size:0`, `clip` or a negative `text-indent` in the page's `<style>` fails. So no CSS class can hide anything, and markup visibility is the whole story.

**2. One semantic stream.** Text is flattened in document order into ITEMS:
- a boundary at every block element;
- a boundary at both edges of every non-formatting element (`span`, `a`, …);
- a boundary between adjacent sibling elements;
- formatting elements (`b`, `em`, `code`, `time`, …) join the text around them.

So `H<b>E</b>AD` is still HEAD, while `<span>…date…</span><span>GIT</span>` keeps GIT a separate token. Whitespace collapses. Removing or replacing the label's wrapper leaves the item unchanged.

**3. Invisible Unicode (provenance checks only).** NFKC is applied, then every Unicode Default_Ignorable code point and format character is removed: `U+034F`, `U+FE0F` and every variation selector, zero-width characters, bidi controls, tag characters, the soft hyphen, and so on. NFKC is applied again, and matching is case-folded. The rendered card copy is never changed.

**4. Channels.**

| Channel | Contents | Used for |
|---|---|---|
| **shown** | none of the three flags | where the required label and date must appear |
| **present** | not "not rendered" (painted or announced), plus `title` / `alt` / `aria-label` / `aria-description` / `placeholder` on non-"not rendered" elements | uniqueness of the source claim and the date |
| **all** | everything, hidden content and every attribute included | the Git scan |

**5. The semantic model** (no CSS class is consulted anywhere):
- **Exactly ONE source claim** (`source:` or `compiled runtime catalog`, any case) on the present channel, in EVERY reading. A shown item reads exactly `Source: compiled runtime catalog · N cards`, where N is `catalog-expect.json`'s total, read on its own, and equals the `<article id>` count from the tree.
- **Exactly ONE date value** on the present channel, in every reading. A shown item reads exactly `generated Mon DD YYYY`, and it is a real calendar date.
- **ZERO Git claims** on the all channel, in every reading:
  - "commit", "@" and "rev-parse" anywhere;
  - "git" and "head" as words;
  - a standalone run of 7+ hex digits. This covers 7–40 character commits and longer hashes (SHA-256).
- **Readings:** a reader may see adjacent inline elements joined or apart. So claims are counted, and Git words searched, in the semantic reading plus every combination of joining or breaking text↔element and element↔element edges, and the strictest result wins. This catches `from <b>HE</b><b>AD</b>`, `2026<b>G</b><b>IT</b>`, and a duplicate label split across spans.

### F1 — eligibility at acquisition time: the architecture

- **One authoritative rule, level-aware.** `isOfferable(_:capstoneInProgress:level:)` now takes the level-up it's judging, and holds every clause: not maxed · not taken this level-up · `requires` · the next tier's gates (`nextTierOpen`: `tierRequires` held and `tierBlockedBy` clear) · not `blockedBy` · not secret · colour and bridge colour active · the capstone lockout. The spread, reroll, random opener and +1 Card all call it.
- **Acquisition re-checks.** `isSelectable(_:atLevel:)` = not taken this level-up, then: the panda by its own schedule (`pandaOffer`), an active capstone by its guarantee seat, everything else by `isOfferable`. The scheduled seats never route through the ordinary rule. `acquire(_:stats:level:)` takes a card only if it is selectable now (a refusal changes nothing); `stillSelectable(_:atLevel:)` filters a table in order and never draws a replacement. `pickCard` stays the raw apply (tests and the rule's own internals only).
- **The scene.** `commitCard` takes the card through `acquire` before any of its effects (a stale choice is refused, never taken). After the Extra Pick's first card, the rest of the table is revalidated: stale cards are dismissed, nothing replaces them, and **if nothing legal remains the level-up resolves** (the synergy and reveal queue flows through `finishLevelUp` as a normal pick). The random opener grants through `acquire` too. Codex recording goes through one path, `UpgradeManager.recordDiscovered` (spread shown, or opener grant).
- **Stalled capstones (Brandon):** only *active* capstones (started, not maxed, next tier open) hold the lockout and receive the every-other-level guarantee.
