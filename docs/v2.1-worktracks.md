Claude thread, all reading THIS repo's docs as shared state.*

## Ground rules (continuity without collisions)

1. **The repo is the shared brain.** Every unit ends with its return packet
   or spec update in `docs/` + a commit. A thread orients by reading:
   `CLAUDE.md` → its own track doc → the reconciliation docs it cites.
2. **One track active at a time on the working tree.** Threads isolate
   CONTEXT, not files — Brandon's validation gates serialize the actual
   edits naturally (he is the bottleneck, by design). No simultaneous
   edits from two threads.
3. **Commit prefixes name the track**: `feat(v2.1-geo):`, `feat(v2.1-abil):`,
   `feat(v2.1-content):` — history stays legible.
4. **Shared-file coordination:** `GameConfig.swift`, `UpgradeManager.swift`,
   and `GameScene.swift` are touched by every track. The rule: a track
   only edits the sections its charter names; anything cross-cutting gets
   a line in this doc's "cross-track notes" before it lands.
5. **Memory:** all threads share the project memory. Each thread updates
   only its own track's clause in the index line.

## Cross-track notes

*(append here when a track touches another's seams)*

- Geometry → Abilities: new placement effects (Lightning Sentry coils,
  Glacial Spikes, black holes) MUST use `PlacementSampler`/`resolve` —
  the primitives exist as of `cd63d6c`.
- Abilities → Content: bestiary/codex ids and Boss Mode dials are shared;
  new-card ids never rename (persistence canon).
- Abilities A0 → Geometry/Content (committed Sep 17):
  `EnemyNode.takeDamage` returns false for an already-dying enemy (no
  second death, no second credit) — Spurhound/Ramplate overrides call
  `super`, so they inherit it. `onEnemyKilled` gains a `source:` parameter
  and credits each enemy once; new enemy types and the Marchwarden's adds
  need nothing beyond calling it. All player damage goes through
  `applyPlayerDamage` — a new hazard (e.g. Ramplate's charge, if it ever
  deals damage) should use `applyBossHazardDamage`, never HP directly.
  Kill paths call `onEnemyKilled(…, source:)` — the parameter is required.
- Abilities A1 → Geometry/Content (Sep 17): `EnemyNode.applyBurn` gained
  `source:` / `stackCap:` (defaults keep old call sites flat + non-stacking).
  Burn/Bleed exist ONLY on `EnemyNode` — the arena bosses (Marchwarden
  included) take no DoTs → scheduled as A4a (Brandon, Sep 17).
- Abilities A2 → Geometry/Content (Sep 17): snowmen are a STUN with a costume
  (`EnemyNode.becomeSnowman`) — any enemy class that respects `isStunned`
  is already compatible. Frozen ground thaws on `swapArena`. Glacial Spikes
  damage bosses via `takeDamage` (3% max HP) when the boss stands on chilled ground.
- Abilities A3 → Geometry/Content (Sep 17): Lightning Sentry coils place via
  `arenaGeometry.isBlocked` / `resolve` (first ability/geometry test case, Q-S3)
  and redeploy on `swapArena`. Arena bosses have NO stun support — Overload's
  boss-class durations reach elites/mini-bosses only (A3 packet, item 1).
- For Geometry Unit 4 (found in the Sep 15 read, deferred by Brandon while
  geometry is parked): killing the Marchwarden in a DEBUG build traps —
  `registerArenaBossDefeat("marchwarden")` looks it up in `ArenaConfig.all`,
  the Splitworks isn't registered yet, and the nil branch is a DEBUG
  `assertionFailure`. Registering the arena in Unit 4 resolves it (or a
  shell-aware `arena(forBossID:)` until then). Release builds unaffected.
