## How a unit runs now (the A4c loop, which worked)

1. **Recon from source first**, using parallel read-only agents. Put every open question in the closure table with a recommendation and a one-line why, then STOP for rulings. Brandon rules in batches; some rows get *modified*, so record his exact wording.
2. **Pure types + a harness** per mechanic, in `Systems/` with Foundation/CoreGraphics only. Mirror any `GameConfig.X` that PlayerStats or UpgradeManager reads into `tools/signature-draw-harness/Stubs.swift`. Put numbers in `GameConfig`.
3. **Gates:** Debug + Release builds, all harnesses, atlas regen, and a static sim proof (TEMP code only in an rsync'd copy; Spark is never driven).
4. **Internal adversarial review:** 5 parallel lenses (rulings conformance, lifecycle, kill credit, geometry, harness/tests). Verify every finding against source before acting. It found a HIGH in A4c (the Carrier never blocked the sweep).
5. **Freeze → independent Reviewer → bounded corrective pass if needed → independent re-review → Brandon device gate.**
   - Step 4's internal adversarial review is implementer self-review. It does **not** substitute for the independent review.
   - Brandon owns the device / player-feel gate and the final creative and release decisions.
   - Snapshot the frozen tree's checksums before any corrective edit, so the corrective diff can be shown on its own.
   - Add focused coverage, plus a **negative control against the pre-fix behaviour**.
   - Keep post-freeze docs edits clearly separate from the implementation.
6. **Close:** one `feat(v2.1-abil):` commit staged **file by file**, push with approval, and republish the Atlas. The commit trailer uses the model you actually are (A4c used `Claude Opus 5.5 <noreply@anthropic.com>`).
