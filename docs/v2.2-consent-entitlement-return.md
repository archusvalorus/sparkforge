# v2.2 entitlement-aware ad startup — bounded revision

This isolated candidate supersedes the original consent correction packet. Owner authorized implementation, tests and independent review only. No ACP, main-tree apply, archive, upload, dashboard setting or website change is included.

## Behavior

Startup first resolves StoreKit Remove Ads ownership. Recognized owners skip all ad-related UMP, ATT and Mobile Ads startup APIs and keep free optional rewards. A positive local ownership cache protects those benefits while current entitlement verification runs. Nonownership requires a completed verified StoreKit enumeration; missing early callbacks, elapsed time, unverified transactions and errors cannot grant ad permission. Unknown users can enter and play the game while ads stay closed. Resolution retries on lifecycle/readiness events, without granting permission on a timer.

Verified nonowners follow UMP update/forms, conditional system ATT, then Mobile Ads startup and generation-checked rewarded loads. Restore calls AppStore.sync only after explicit user action. Purchase/restore operations serialize, and verified purchase/transaction ownership takes effect before awaiting transaction finish. Revision tokens and cancellation prevent a stale empty snapshot from overriding a newer owner. Revocation closes the gate until fresh verified enumeration completes. Skin purchases and existing purchase keys remain intact.

Ownership changes invalidate queued/cached ad work. Stale UMP/form/ATT callbacks cannot advance a later ownership session. An SDK initialization or system sheet already started while a confirmed nonowner cannot be undone retroactively after purchase; subsequent startup stages, loads and presentations are blocked. Already-earned rewards remain exactly once. This is not a claim that an initialized SDK is unloaded or that all historical partner traffic is reversed.
