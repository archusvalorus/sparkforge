## What Apple actually said, and why it happened

The reviewer asked for "a demo account that has already drew the panda cards in
the app" — Apple boilerplate colliding with the game's own design. Sparkforge
has no accounts at all, and the panda content is behind:

1. a **9.27% per-run eligibility roll** (`GameConfig.Panda.eligibilityChance`),
2. surviving to the **level 2–5 offer window**,
3. choosing a card whose entire visible text is `???`.

The v2.0 deadlock fix made *finding the tree* open the skin family — but the
tree itself is deliberately near-unfindable, so the $9.99 Flame Panda IAP was
unreachable in any review session. All the existing seams
(`debugAlwaysEligible`, `debugUnlockAll`) are `#if DEBUG` and don't exist in
the reviewed binary. A demo video is explicitly "not sufficient" per the
rejection; Apple's own suggested remedy is **a demonstration mode**, so that's
the fix.

## The fix — Review Mode (build 7)

A release-compiled, hidden, persistent toggle. Decision made Aug 7 (Brandon):
**reveal + force eligibility**, granting nothing.

- **Trigger:** tap the version label at the bottom of the title footer
  **7 times** (`ReviewMode.tapsToToggle`, 2s max gap between taps). Same
  gesture toggles it off. State persists in `sf_review_mode_active`.
- **While active:** the Panda family renders revealed at the skin hub
  (non-persistent — mask returns when the mode goes off), and **every run is
  panda-eligible** so a reviewer can draw the cards.
- **Grants nothing:** the earned panda skin still wants the capstone; Flame
  Panda still goes through StoreKit. A player who finds the gesture only
  spoils the secret for themselves.
- **Announces itself** (studio seam rule): the version label flips to
  `⚠︎ REVIEW MODE` in warning gold, and the run HUD paints
  `⚠︎ REVIEW MODE — panda always eligible`.
- Touch points: `Systems/ReviewMode.swift` (new), `SkinManager.isFamilyRevealed`,
  `UpgradeManager.rollRunMutations`, `GameScene.setupHUD`,
  `TitleScene` footer + `handleVersionLabelTap`.

## Fixed Jul 28 — worth reading, all found by PLAYING

Three unlock bugs, none of which could fail loudly, all surfaced by playing as a
new user rather than by reading code:

- **The panda skin had no unlock call anywhere.** The card set `pandaTier` 1..5
  and stopped. The secret tree had no payoff at all.
- **Star-Crossed was gated behind the Mote**, whose encounter needs 10,000
  lifetime kills. Clearing Arena 5 granted nothing, contradicting the skin's own
  blurb. Arena 4's boss had always granted Ascended correctly; Arena 5's line was
  simply missing.
- **Flame Panda was unpurchasable.** The hub only makes a *revealed* family
  tappable, and a secret family revealed only by owning a member. With the panda
  skin unreachable, the family could never open, so the $9.99 IAP could only be
  bought from inside a room you could only enter by already owning something in
  it. Discovered because the ASC review screenshot couldn't be taken. *(The
  2.1(a) rejection is this bug's sibling: the door now opens from the tree, but
  a reviewer can't find the tree. Review Mode is the third and final key.)*

Also: the skin picker drew palette only, so every premium skin looked like a
recolour of its free sibling at the point of purchase and Flame Panda previewed
as a plain orange dot. Previews now compose overlays and sprites. And the pause
menu's MENU button quit instantly with no confirmation.

## Operating discipline (reusable, not v2.0-specific)

- **`docs/character-art-playbook.md`** — the mold. Size before commissioning,
  points not pixels, body-raster/effects-procedural, animate by screen time,
  union-box cropping, and the warning that animated sprites do not render at the
  size the arithmetic predicts.
- **`docs/art-briefs.md`** — what was asked for and the creative intent.
- **`art/source/<character>/`** — drop folders with the naming convention.
  Sources committed so assets can be re-cut without Lyra.
- **`docs/v2.0-asc-iap-setup.md`** — App Store Connect field rules, learned the
  hard way. Read before touching IAPs again.

**Skin tier rule:** earned skins RE-TINT; premium skins add FORM and FIRE.

**Sprite vs procedural rule:** does it need to keep being Spark? Yes → palette or
overlay. No → sprite.

**Face rule:** anything that reads as part of the face rides `eyesNode`, so it
travels with the eyes. Static features under darting eyes read as a second, dead
pair of eyes.

**Secrets rule:** gate on discovery, not on ownership. You cannot spoil a secret
for someone who has already found it.

All of the above are also locked in the Notion Game Design Decision Log under
*Sparkforge v2.0 "The Arrival"*.
